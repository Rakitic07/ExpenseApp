# Spendly-Plus — Mobile (React Native)

The native phone app for **Spendly-Plus**. It is a pure **React Native** app
(native UI, no WebView) that talks to the existing Next.js backend on Vercel via
its `/api` routes using Bearer-token auth. The web app + backend live one level
up in `../` (the Next.js project) and are unchanged by this folder.

## Why React Native now (we used Capacitor before)

Earlier the phone app was built with **Capacitor** — it wrapped the deployed
Next.js website inside an Android **WebView**. That approach kept stuttering
while scrolling/navigating because a WebView repaints HTML/CSS (blur, shadows,
DOM) on the JS/main thread every frame.

We've **replaced Capacitor with React Native**. Every screen is now rendered
with real native views (`View`, `Text`, `FlatList`, Skia-accelerated charts), so
scrolling and transitions run at native speed. The old Capacitor artifacts
(`../android/`, `../ios/`, `capacitor.config.ts`, etc.) were removed; this
`mobile/` folder is the single source for the phone app.

> The **"Download for Android"** button on the website is unaffected — it links
> to the APK published on the GitHub release
> (`releases/latest/download/spendly-plus.apk`), independent of how the app is
> built.

## Tech stack

- React Native 0.86 (bare CLI), Hermes, New Architecture (Fabric/TurboModules)
- React Navigation (native-stack + bottom-tabs)
- `victory-native` (Skia) for charts, `react-native-svg` for the budget ring
- `react-native-reanimated` 4 + `react-native-worklets` + `react-native-gesture-handler`
- `@react-native-async-storage/async-storage` for offline cache + auth token
- Bill scanning (on-device, offline): `react-native-image-picker` (camera/gallery),
  `@react-native-ml-kit/text-recognition` (Google ML Kit OCR),
  `@bam.tech/react-native-image-resizer` + `@dr.pogodin/react-native-fs` (tiny thumbnail)

## Bill scanning (camera → auto-fill)

Tap **Scan a bill** on the Add/Edit expense screen to capture a photo (or pick one
from the gallery). The flow is fully **on-device and offline**:

1. `react-native-image-picker` captures the photo (Android asks for CAMERA once).
2. `@react-native-ml-kit/text-recognition` (Google ML Kit) runs OCR locally — the
   image never leaves the phone.
3. `src/lib/billParser.ts` (pure JS, no network/LLM) extracts amount, date,
   merchant → title, a best-guess category, and payment mode/provider using
   multilingual keyword + number/date heuristics.
4. The Add-expense form is the **editable preview**: whatever was read is
   pre-filled; the user completes anything missing (e.g. "Paid by") and taps Add.

**Storage / privacy.** The full photo is discarded. Only a **tiny thumbnail**
(~120px grayscale-ish JPEG, hard-capped to ≈10KB / 14000 base64 chars) is kept,
stored in the `Expense.thumbnail` column so a small preview shows when you edit the
entry later on any device. If the thumbnail can't get under the cap, it's dropped
rather than bloating the DB.

> **Rebuild required.** These are native modules. After pulling this change run
> `make android` (a full rebuild, not just Metro) so autolinking picks them up.

> **Backend/DB.** The `thumbnail` column was added to both Prisma schemas. Locally
> it's already applied (`npm run db:push:local`). On production Postgres run
> `npm run db:push` (or a migration) after deploying, otherwise create/edit will
> fail with a missing-column error (same as when `paymentMode` was added).

## Prerequisites (one-time)

You need a JDK, the Android SDK, and the Android NDK. On macOS the `Makefile`
can install everything via Homebrew:

```sh
cd mobile
make setup      # installs JDK 17 + Android SDK 36 + NDK 27.1 + cmake (Homebrew)
make doctor     # verify the toolchain was detected
```

Required versions (see `android/build.gradle`): **compileSdk/target 36**,
**build-tools 36.0.0**, **NDK 27.1.12297006**, **JDK 17** (Gradle 9.3 needs 17+).

If your Android SDK lives somewhere other than the Homebrew path, override it:

```sh
make android ANDROID_HOME="$HOME/Library/Android/sdk"
```

## Install JS dependencies

```sh
make deps       # == npm install
```

## Build the APK

```sh
make android    # -> outputs/spendly-plus.apk
```

Then install `outputs/spendly-plus.apk` on your phone, or upload it to the
GitHub release so the website's "Download for Android" button serves it.

Other targets:

```sh
make install    # build + `adb install -r` onto a connected device
make dev        # start the Metro bundler (JS dev server)
make run        # install a debug build + run on device/emulator
make clean      # clean android build artifacts
make help       # list all targets
```

## CPU architectures (build speed vs. device coverage)

Building native C++ (Skia, reanimated, Hermes, Fabric) for **all** ABIs is the
biggest cause of slow builds. By default we build a **single ABI** —
`arm64-v8a` — which covers virtually every modern phone. This is set in
`android/gradle.properties`:

```properties
reactNativeArchitectures=arm64-v8a
```

Need broader coverage (older 32-bit phones, or an x86/x86_64 **emulator**)?
Override on the CLI for that build only:

```sh
cd android
./gradlew assembleRelease -PreactNativeArchitectures=armeabi-v7a,arm64-v8a,x86,x86_64
```

**Why the first build is slow (and later ones are fast):**

- The first run downloads Gradle 9.3 + all dependencies (one-time).
- Skia + reanimated/worklets compile their native C++ once, then it's **cached**.
- We enable the Gradle **daemon + parallel + build caching** and give the JVM
  more memory (`android/gradle.properties`), so subsequent builds are
  incremental — usually seconds to about a minute.

## Troubleshooting

### `[Reanimated] react-native-worklets library not found`
Reanimated 4 needs **`react-native-worklets`** as a *direct* dependency so React
Native autolinking can find it (a transitive copy isn't enough). It's already in
`package.json`; if the error appears, reinstall it explicitly:

```sh
npm install react-native-worklets@0.11.3 --save-exact
npx react-native config   # should list react-native-worklets under dependencies
```

The Reanimated worklets Babel plugin must also be **last** in `babel.config.js`:

```js
plugins: ['react-native-worklets/plugin'],
```

### `SDK location not found` / `Android SDK missing`
Run `make setup`, or point the build at your SDK:

```sh
make android ANDROID_HOME="$HOME/Library/Android/sdk"
```

`make android` writes `android/local.properties` (`sdk.dir=...`) automatically.

### `Unsupported class file major version` / wrong Java
Gradle 9.3 needs **JDK 17+**. Check what's detected with `make doctor`. Install
17 with `brew install openjdk@17` (the Makefile prefers 17, then 21).

### NDK / cmake errors during C++ compile
Ensure the exact NDK is installed:

```sh
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" "ndk;27.1.12297006" "cmake;3.22.1"
```

### App installs but shows a red screen / "Unable to load script"
That's a **debug** build looking for Metro. Either run `make dev` in another
terminal, or install the **release** APK from `make android` (self-contained,
no Metro needed).

### App can't reach the backend / login fails
Check `src/config.ts` → `API_BASE` points to your deployed backend, and the
device has internet. The app is offline-first, so cached data still shows and
changes sync once the network returns.

### Build got slow again
Confirm `android/gradle.properties` still has `reactNativeArchitectures=arm64-v8a`
and the `org.gradle.parallel/caching` flags. A `make clean` forces a full
rebuild (slow); avoid it unless the build is corrupted.

### "Scan a bill" does nothing / camera won't open
The scanning modules are native. If you added them via `git pull`, you must run a
**full rebuild** (`make android`) — a Metro reload alone won't link them. On first
use Android prompts for the CAMERA permission; if you denied it, re-enable it in
Settings → Apps → Spendly-Plus → Permissions.

### Create/edit fails after adding scanning ("column thumbnail does not exist")
The `Expense.thumbnail` column isn't on the (production) database yet. Run
`npm run db:push` against prod (locally use `npm run db:push:local`).
